# 治理背景：第三方 SDK、数据基础设施与推断敏感性

## 地位

这是当前不发展的数据治理背景候选。它保留第三方基础设施、传感器权限和推断性敏感数据的叙事价值；不确认任何现实应用实际收集、共享或滥用了某类数据。

## 从可见应用到不可见基础设施

用户面对的是一个 App 或服务，实际的数据与行动链可能包含：

- 宿主应用及其第一方代码；
- 登录、支付、广告、统计、归因、推送、崩溃报告或社交分享 SDK；
- 操作系统权限、无需显式授权的传感器接口与后台组件；
- SDK 提供者、母公司、数据处理者、云服务和数据经纪网络；
- 由原始行为形成的特征、画像、受众标签和模型输出；
- 最后依据输出采取行动的广告商、平台、雇主、保险人或公共机构。

这种链条适合表现责任怎样被分散：每一方都声称自己只提供一个小功能，整体却形成用户难以看见、理解或拒绝的数据基础设施。

## 证据强度必须分层

- Manifest 中声明某项权限，只能证明应用请求或可能使用它，不证明运行时一定调用。
- 检测到某个 SDK 或组件，只能证明代码或配置存在，不证明某类数据已经传输、由谁接收或用于何种目的。
- 两个应用包含同一 SDK，不证明它们共享了特定用户的内容、身份或画像。
- 用户在谈话后看到相关内容，不足以证明设备偷听；共同位置、搜索行为、联系人、广告生态、选择性记忆或其他路径都可能造成相似体验。
- 从静态代码推断真实数据流，需要与动态网络观察、版本、权限状态、隐私说明及后端行为等证据结合。

这些边界不仅用于现实研究，也能使小说中的调查情节更可信：角色可能先从权限或组件发现风险线索，却不能把线索立刻当作完成的指控。

## 从普通行为到推断性敏感特征

观看、停留、滑动、设备运动、位置近接和内容互动看似普通，组合以后可能被模型用于推断政治倾向、健康状态、性取向、经济脆弱性或其他敏感特征。真正产生差异待遇的可能不是原始记录，而是不可见的 embedding、分数、相似群体或商业标签。

这仍需保持三项区分：

- 模型能够推断，不等于推断正确；
- 推断在伦理上敏感，不等于在所有法域都已经具有同一法律分类；
- SDK 可以成为数据链的基础设施，不表示每个 SDK 都自行完成全部画像或出售标签。

## 传感器与交互控制

某些传感器访问可能不以用户熟悉的“危险权限”弹窗出现，却能被用于广告跳转、指纹识别、活动推断或其他交互。它的风险不只在秘密收集，也可能在利用身体动作触发用户不想要的页面、购买流程或注意力转移。

若进入文学情节，可以把“设备只是感受到一次晃动”与“商业系统把这次晃动解释为同意或兴趣”之间的断裂写出来；不能把具体技术实现或权限等级写死在未研究状态。

## 使用边界

本候选不指向任何特定现实 App、公司、SDK 或个人，也不证明某条现实数据流存在。若具体权限、组件、数据流或法律分类进入作品或论文，必须依据可靠公开材料重新核验。
