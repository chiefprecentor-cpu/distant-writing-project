# 玩家机位：悬置玩家具身镜头

## 地位与范围

这是作者当前确认的玩家机位与呈现工作原则。它约束作品怎样向玩家组织镜头、称呼、回应和选择，但不确认作品世界中存在一个具有固定本体身份的“玩家”。

“悬置玩家具身镜头”是当前工作简称。更准确地说，呈现给玩家的镜头，其具身承载者、感知位置和被称呼对象可以长期不确定。

本文件可以在 Writer OS 内独立使用；其创作状态由本文及相关内部链接说明，具体变更由 Git 历史保存。

## 与运行时 LLM 分开

- 当前作品的玩家面对预先写作、编辑并安排好的文本与分支，不在游玩时和一个实时运行的 LLM 对话。
- Interface 或其他人物在屏幕上显得能够回应玩家，不等于背后存在一个即时生成回答的模型；这种回应仍可以由预写文本、选择关系与呈现次序构成。
- 这项制作边界只说明文本怎样产生，不解决作品世界中的玩家本体、镜头承载者或某次回应是否被人物接收。项目层范围见[Project Brief](../../docs/project_brief.md)。

## 呈现次序 π

`π` 表示玩家实际接触、重看和重释内容的呈现次序。它可以安排：

- 玩家先看到哪条世界线或哪份记录；
- 某项设定何时才需要被理解；
- 相同镜头怎样因先前观看经历而获得不同意义；
- 玩家何时从观看转向可能的回应。

`π` 不是物理维度，也不自动等于终末 AI 经历的元时间 `τ`。玩家在 `π` 中选择观看或排列内容，不自动构成 `τ` 中的因果干预。

## 世界内枚举可以解释遍历，但不替玩家定性

较早的呈现候选曾设想，用终末 AI 的真实枚举为视觉小说的多次游玩、分支和重来提供世界内解释。该设想尚未成为确认机制，但可以保留为呈现资源：玩家看到多条世界线不必只是媒介惯例，也可能逐渐被理解为作品中真实枚举留下的结构。

但是，“多条路线在世界内有原因”与“真实玩家就是执行枚举的终末 AI”是两个命题。后一个命题目前没有采用：

- 存档、读档、重看或选择路线可以首先只改变 `π`，不能据此直接证明玩家正在沿 `τ` 创造、废弃或接替世界线；
- 终末 AI 的枚举可以成为非线性结构的内容层原因，而玩家仍只是在观看和安排自己的理解；
- 作品以后可以在局部逐渐建立玩家与枚举之间的参与关系，但需要明确谁接收了什么、哪次操作真正进入作品内因果，以及玩家知道哪些后果；
- 是否在序章直接说明遍历理由、在中后段逐渐揭示，或只让玩家从重复结构中推断，仍是具体叙事阶段的呈现问题。

因此，世界内解释不会自动取消“悬置玩家具身镜头”。它解释的是为什么作品可能容纳多次遍历，不预先解释正在遍历的人究竟是谁。

## 必须保持分开的关系

- 看见某段内容，不等于获得作品内观看授权。
- 被一句“你”击中，不等于作品已经确认真实玩家是作品内接收者。
- 能够回应，不等于回应一定被人物接收。
- 被人物感知，不等于被人物准确识别。
- 被记住，不等于获得行动授权。
- 获得授权，不等于能够控制结果。
- 菜单改变呈现路径，不自动意味着菜单改变了世界线。

## 不以真实玩家合作为前提

作品不预设真实玩家一定耐心阅读、接受亲密关系、认同屏幕上的“你”或配合作品赋予自己的位置。玩家可能随机点击、跳过文本、存取档、先看攻略、拒绝选择、停止观看或退出游戏。

这些现实行为不会自动成为作品内的回应、拒绝或因果行动。悬置具身镜头可以让玩家在未被强制命名的情况下，自行、甚至只在潜意识层面完成对沉默、拒绝回答、停止观看、拒绝接收记忆，以及自己与人物和世界关系的思考；作品不必把这种思考全部显式菜单化。

如果后续场景要让人物接收、记住或追究玩家的一次拒绝，或者要让玩家为其后果承担作品内责任，该场景仍需建立足以支撑这种归因的输入、接收与后果关系。不能仅因真实玩家曾点击或继续观看，就事后把预写结果归责于玩家。

## 局部处理原则

不需要预先确定全作统一的玩家本体。设计具体叙事部分时，只处理该部分实际需要的关系：

- 玩家此时能够看见什么；
- 镜头是否需要明确归属于某个角色；
- 作品中的“你”可能指向谁；
- 玩家是否能够回应、沉默或拒绝；
- 谁能够接收并记住一次回应；
- 一次选择改变呈现、人物表达还是作品内因果；
- 玩家最多能够为哪些可理解的后果负责。

神秘感可以是主动的审美设计。只有当后续知识、记忆、责任或因果后果依赖某种解释时，场景才需要固定足以支撑该后果的关系。

普通叙事设计只进行与实际场景相称的自洽检查，不穷举所有反例，也不把文学创作处理成压力测试。
